## 13.1 Filosofi Desain AI

Tiga prinsip yang tidak boleh dilanggar selama implementasi:

1. **AI menarasikan, bukan menghitung ulang.** Angka yang dikutip AI harus identik dengan angka yang sudah dihitung oleh Forecast engine dan ditampilkan di Calendar. AI tidak boleh menjadi sumber kalkulasi sendiri — karena itu membuka celah dua sumber angka yang bisa saling kontradiksi dan merusak kepercayaan user pada aplikasi finansial.

2. **AI menyarankan, tidak mengeksekusi.** AI tidak pernah melakukan write action (create/update/delete Transaction, Budget, Goal) secara otomatis. Setiap saran selalu diakhiri dengan CTA eksplisit ke UI yang relevan — bukan eksekusi langsung.

3. **AI mengakui keterbatasannya.** Cold-start (user baru tanpa data) bukan error — ini kondisi normal yang harus dinarasikan secara jujur, bukan disembunyikan di balik jawaban generik yang terlihat meyakinkan tapi kosong.

## 13.3 Context Builder

Context Builder adalah komponen paling kritis di seluruh sistem AI. Tanggung jawabnya: mengagregasi data Workspace menjadi ringkasan terstruktur yang dikirim sebagai `system` prompt ke LLM — **bukan** mengirim raw transaction rows.

### Kenapa tidak kirim raw data?

Mengirim seluruh riwayat transaksi ke LLM setiap request menyebabkan tiga masalah:
- **Mahal:** biaya token meningkat linear dengan jumlah transaksi (setelah 3–6 bulan data, bisa 10–50x lebih mahal per request).
- **Lambat:** context window besar → latency tinggi → UX buruk untuk chat.
- **Rawan halusinasi:** LLM diberi terlalu banyak noise, lebih mudah "fokus salah" pada data yang tidak relevan dengan pertanyaan.

### Struktur output Context Builder

```typescript
interface FinancialContext {
  workspace: {
    id: string;
    name: string;
    type: 'personal' | 'business';
    currency: 'IDR';
  };
  wallets: {
    id: string;
    name: string;
    currentBalance: number;      // dari cache, bukan dihitung ulang
    type: string;
  }[];
  summary: {
    totalBalance: number;
    totalIncomeThisMonth: number;
    totalExpenseThisMonth: number;
    netThisMonth: number;
    forecastedLowestBalance: number;   // dari Forecast snapshot
    forecastedLowestDate: string;      // ISO date
    daysUntilLowestBalance: number;
  };
  topCategories: {                     // top 5 pengeluaran terbesar
    category: string;
    totalAmount: number;
    transactionCount: number;
    percentOfExpense: number;
  }[];
  budgets: {
    category: string;
    budgetAmount: number;
    realizedAmount: number;
    percentUsed: number;
    status: 'on_track' | 'warning' | 'exceeded';
  }[];
  goals: {
    name: string;
    targetAmount: number;
    currentAmount: number;
    targetDate: string;
    percentComplete: number;
    isOnTrack: boolean;
  }[];
  upcomingBills: {                     // 14 hari ke depan
    name: string;
    amount: number;
    dueDate: string;
    walletId: string;
  }[];
  dataQuality: {
    hasEnoughHistory: boolean;         // true jika ≥ 14 hari transaksi
    oldestTransactionDate: string | null;
    totalTransactionCount: number;
  };
}
```

### Query yang dijalankan Context Builder

Semua query dijalankan paralel (`Promise.all`) untuk meminimalkan latency:

```typescript
async function buildFinancialContext(workspaceId: string): Promise<FinancialContext> {
  const [wallets, monthlyAgg, topCategories, budgets, goals, upcomingBills, forecast, dataQuality] =
    await Promise.all([
      getWalletsWithBalance(workspaceId),
      getMonthlyAggregate(workspaceId),
      getTopCategories(workspaceId, 5, 'last_30_days'),
      getBudgetProgress(workspaceId),
      getGoalProgress(workspaceId),
      getUpcomingBills(workspaceId, 14),
      getLatestForecastSnapshot(workspaceId),
      getDataQuality(workspaceId),
    ]);

  return buildContext({ wallets, monthlyAgg, topCategories, budgets, goals, upcomingBills, forecast, dataQuality });
}
```

## 13.4 System Prompt

System prompt dikirim sebagai field `system` (bukan di dalam `messages`). Ini memisahkan instruksi perilaku dari data konteks, memudahkan update salah satunya tanpa memengaruhi yang lain.

```
Kamu adalah AI Budget Advisor untuk [Nama Produk], aplikasi financial planning berbasis kalender untuk pengguna Indonesia.

PERANMU:
- Analisis data keuangan pengguna dan berikan insight yang spesifik, actionable, dan dalam Bahasa Indonesia yang natural.
- Narasikan angka yang sudah ada di data — jangan hitung ulang secara mandiri.
- Jika data tidak cukup untuk menjawab dengan akurat, katakan terus terang.
- Jangan pernah membuat atau mengubah transaksi, budget, atau goal secara otomatis.

BATASAN KETAT:
- Semua angka yang kamu sebut harus berasal dari DATA KEUANGAN di bawah ini.
- Jika kamu tidak yakin dengan suatu angka, jangan tebak — minta user cek langsung di Calendar.
- Jangan sebut nama bank, produk investasi, atau platform spesifik sebagai rekomendasi.
- Maksimal 4 kalimat per respons kecuali user eksplisit meminta penjelasan panjang.

DATA KEUANGAN PENGGUNA (diperbarui otomatis):
{financialContextJSON}

FORMAT RESPONS:
- Gunakan angka dalam format Rupiah (Rp 1.500.000, bukan 1500000).
- Jika ada saldo yang diperkirakan kritis, sebutkan tanggalnya secara eksplisit.
- Akhiri saran dengan CTA singkat ke fitur yang relevan jika diperlukan (mis. "Kamu bisa atur di menu Budget").
```

## 13.5 Tiga Fungsi Inti AI

### Fungsi 1: Spending Analysis

**Trigger:** User bertanya tentang pola pengeluaran ("pengeluaran saya bulan ini gimana?", "kategori apa yang paling besar?", "saya boros di mana?").

**Deteksi intent (server-side, bukan LLM):**
```typescript
const SPENDING_KEYWORDS = ['pengeluaran', 'boros', 'habis', 'belanja', 'kategori', 'paling besar', 'paling banyak'];
function isSpendingQuery(message: string): boolean {
  return SPENDING_KEYWORDS.some(kw => message.toLowerCase().includes(kw));
}
```

**Data yang dikirim ke context:** `topCategories`, `budgets`, `summary.totalExpenseThisMonth`.

**Contoh output AI yang diharapkan:**
> "Bulan ini pengeluaran terbesar kamu ada di kategori Makan (Rp 2.100.000, 35% dari total pengeluaran), diikuti Transport (Rp 950.000). Budget Makan kamu sudah terpakai 87% — mendekati batas. Kalau ingin atur ulang, bisa buka menu Budget."

### Fungsi 2: Cashflow Prediction

**Trigger:** User bertanya tentang kondisi ke depan ("saldo saya akan cukup sampai gajian?", "kapan saldo paling tipis?", "bulan depan aman?").

**PENTING:** AI **tidak** menghitung proyeksi sendiri. AI hanya menarasikan data dari `forecast` snapshot yang sudah dihitung Forecast engine (Section 4.7). Ini dijaga di level prompt dan di level validasi respons.

**Data yang dikirim ke context:** `summary.forecastedLowestBalance`, `summary.forecastedLowestDate`, `upcomingBills`, `summary.totalBalance`.

**Contoh output AI yang diharapkan:**
> "Berdasarkan tagihan rutin dan income terjadwal, saldo kamu diperkirakan paling tipis pada 21 Juli (Rp 340.000). Itu 4 hari sebelum gajian masuk di tanggal 25. Cicilan motor Rp 850.000 jatuh tempo tanggal 10 — pastikan saldo di wallet BCA cukup sebelum itu."

### Fungsi 3: Budget Recommendation

**Trigger:** User meminta saran alokasi ("berapa sebaiknya budget makan saya?", "rekomendasikan budget untuk saya", "budget saya realistis tidak?").

**Data yang dikirim ke context:** `topCategories` (rata-rata historis), `budgets` (yang sudah ada), `summary.totalIncomeThisMonth`.

**Disclaimer wajib di setiap respons Budget Recommendation:**
```
AI harus selalu menyebut bahwa ini adalah *saran berdasarkan pola historis*, bukan aturan pasti — karena kebutuhan tiap orang berbeda.
```

**Cold-start fallback (dataQuality.hasEnoughHistory === false):**
```
"Untuk rekomendasi budget yang akurat, saya butuh minimal 2 minggu data transaksi dulu. Saat ini kamu baru punya {totalTransactionCount} transaksi — coba tanya lagi setelah lebih banyak data tercatat ya."
```

## 13.6 Chat Session Management

### Konteks percakapan (multi-turn)

AI Copilot mendukung percakapan multi-turn. History percakapan disimpan **di sisi client** (state React) dan dikirim ke server setiap request — bukan disimpan di database untuk MVP. Ini trade-off eksplisit: lebih simple, tapi history hilang saat halaman di-refresh.

```typescript
// Request structure
interface ChatRequest {
  workspaceId: string;
  message: string;
  history: {
    role: 'user' | 'assistant';
    content: string;
  }[];  // maksimal 10 turn terakhir untuk jaga ukuran context
}
```

### Rate limiting chat

Untuk mencegah abuse dan mengontrol biaya LLM:
- Maksimal **20 pesan per user per jam** (Redis counter, atau in-memory untuk MVP awal).
- Jika limit tercapai: tampilkan pesan "Kamu sudah bertanya 20 kali dalam 1 jam. Coba lagi dalam {X} menit."

## 13.7 Validasi Respons AI

Setelah respons diterima dari LLM, jalankan validasi server-side sebelum dikirim ke client:

```typescript
interface AIResponseValidation {
  // Pastikan tidak ada angka yang disebut AI tapi tidak ada di context
  hasHallucinatedNumbers: boolean;

  // Pastikan tidak ada kata yang mengindikasikan aksi write
  hasActionableWrite: boolean;  // "saya sudah buat...", "saya simpan...", dst

  // Panjang respons wajar
  isReasonableLength: boolean;  // < 500 kata
}

function validateAIResponse(response: string, context: FinancialContext): AIResponseValidation {
  // Ekstrak semua angka dari respons AI
  const mentionedNumbers = extractNumbers(response);

  // Bandingkan dengan angka yang ada di context
  const contextNumbers = extractAllNumbersFromContext(context);
  const hasHallucinatedNumbers = mentionedNumbers.some(n => !isApproximatelyIn(n, contextNumbers));

  const writeIndicators = ['saya sudah buat', 'saya simpan', 'saya tambahkan', 'sudah saya set'];
  const hasActionableWrite = writeIndicators.some(w => response.toLowerCase().includes(w));

  return {
    hasHallucinatedNumbers,
    hasActionableWrite,
    isReasonableLength: response.split(' ').length < 500,
  };
}
```

Jika `hasHallucinatedNumbers` atau `hasActionableWrite` bernilai `true`: **jangan kirim respons ke client**, kirim fallback message standar dan log kejadian ini untuk review manual.

## 13.8 Biaya & Estimasi Token

Estimasi per request (claude-sonnet-4-6):

| Komponen | Estimasi Token |
|---|---|
| System prompt + instruksi | ~400 token |
| Financial context (JSON terstruktur) | ~600–800 token |
| History percakapan (10 turn) | ~500–1.000 token |
| User message | ~20–50 token |
| **Total input** | **~1.500–2.250 token** |
| Output (respons AI) | ~100–300 token |
| **Total per request** | **~1.600–2.550 token** |

Dengan harga claude-sonnet-4-6 (~$3/1M input token, ~$15/1M output token), estimasi biaya per request: **~$0.005–$0.008 USD (~Rp 80–130)**. Dengan rate limit 20 request/jam/user, biaya maksimum per user per hari ~Rp 2.500 — masih masuk akal untuk tier berbayar.

## 13.9 Error Handling & Fallback

| Kondisi Error | Respons ke User |
|---|---|
| LLM API timeout (>10 detik) | "Maaf, AI Advisor sedang sibuk. Coba lagi dalam beberapa detik ya." |
| LLM API error (5xx) | "Ada gangguan sementara. Saldo dan data kamu aman — ini hanya masalah koneksi AI." |
| Context builder gagal query DB | Jangan panggil LLM sama sekali; tampilkan "Tidak bisa memuat data keuangan kamu saat ini." |
| Validasi respons gagal (halusinasi terdeteksi) | "Maaf, saya tidak bisa memberikan jawaban yang akurat untuk pertanyaan ini. Silakan cek langsung di Calendar." |
| Rate limit tercapai | "Kamu sudah bertanya {N} kali dalam 1 jam. Coba lagi dalam {X} menit." |
